Steering the AGV
with a thumbs-up gesture

The gesture_to_car_control_node turns a single hand gesture ??four fingers curled into a fist with the thumb extended ??into a directional drive command. The direction the thumb points maps directly onto one of the four mecanum motions: forward, reverse, strafe-left or strafe-right.

01 / Concept

Gesture pipeline overview

Hand-gesture control spans two ROS2 nodes. The perception node (hand_gesture_recognition_node in the perception package) runs MediaPipe Hands on the camera image and publishes 21 hand-landmark 3-D points as a custom Gesture message. The decision node ??gesture_to_car_control_node ??reads those landmarks and maps the thumb direction to a motion command.

  • raw_gesture_data ??interface/msg/Gesture ??21 MediaPipe landmarks (wrist + 4 fingers ? 5 points).
  • /car_movement_control ??interface/msg/CarControl ??physical speed command for the selected direction.
  • gesture_control_enabled ??std_msgs/msg/Bool ??latched on/off switch published by the joystick node.
02 / Hand Landmarks

MediaPipe 21-point hand model

MediaPipe Hands outputs 21 landmarks per hand, each as an (x, y, z) point normalised to the image frame. The node uses named constants from the Gesture message definition to access them by role rather than by magic index number.

landmark indices used by the node 
# Wrist anchor
Gesture.WRIST           # 0 ??base of the palm

# Thumb
Gesture.THUMB_MCP       # 2 ??thumb knuckle (metacarpal-phalangeal joint)
Gesture.THUMB_TIP       # 4 ??thumb fingertip

# Four fingers (used for fist-curl detection)
Gesture.INDEX_TIP       # 8   INDEX_PIP  # 6
Gesture.MIDDLE_TIP      # 12  MIDDLE_PIP # 10
Gesture.RING_TIP        # 16  RING_PIP   # 14
Gesture.PINKY_TIP       # 20  PINKY_PIP  # 18

The node requires a complete 21-landmark array. If len(msg.landmarks) < 21, the callback publishes a stop command and returns early ??preventing corrupt partial detections from moving the robot.

03 / Gesture Check

Detecting the thumbs-up gesture

Before reading thumb direction the node first confirms the hand is showing the correct gesture: four fingers curled (fist) and the thumb clearly extended. This two-step check rejects unintentional open-hand frames.

is_thumb_gesture ??fist + extended thumb 
def is_thumb_gesture(self, msg):
    wrist = msg.landmarks[Gesture.WRIST]

    # Step 1: all four fingers must be curled into a fist
    fingers = [
        (Gesture.INDEX_TIP,  Gesture.INDEX_PIP),
        (Gesture.MIDDLE_TIP, Gesture.MIDDLE_PIP),
        (Gesture.RING_TIP,   Gesture.RING_PIP),
        (Gesture.PINKY_TIP,  Gesture.PINKY_PIP),
    ]
    for tip_idx, pip_idx in fingers:
        if not self.is_finger_curled(
                msg.landmarks[tip_idx], msg.landmarks[pip_idx], wrist):
            return False   # at least one finger is open ??not a fist

    # Step 2: thumb tip must be farther from the wrist than thumb MCP
    return self.is_thumb_extended(
        msg.landmarks[Gesture.THUMB_TIP],
        msg.landmarks[Gesture.THUMB_MCP],
        wrist)

def is_finger_curled(self, tip, pip, wrist):
    # Curled: tip?“wrist distance ??PIP?“wrist distance ? curl_ratio
    return self.dist(tip, wrist) <= self.dist(pip, wrist) * self.curl_ratio

def is_thumb_extended(self, thumb_tip, thumb_mcp, wrist):
    # Extended: tip?“wrist distance ??MCP?“wrist distance ? thumb_extend_ratio
    return self.dist(thumb_tip, wrist) >= self.dist(thumb_mcp, wrist) * self.thumb_extend_ratio

The distance helper uses the full 3-D Euclidean norm so the check works regardless of hand rotation or depth from the camera.

04 / Direction

Mapping thumb direction ??motion

Once the gesture is confirmed, the node computes a 2-D direction vector from the thumb MCP (knuckle) to the thumb tip, then compares the horizontal and vertical components to find the dominant axis. The mapping is mirror-corrected: because the camera sees a mirror image of the user, left/right are swapped so the robot moves in the direction that feels natural.

listener_callback ??direction logic 
# Direction vector: thumb tip ??thumb knuckle (MCP)
thumb_tip = msg.landmarks[Gesture.THUMB_TIP]
thumb_mcp = msg.landmarks[Gesture.THUMB_MCP]
thumb_vx  = thumb_tip.x - thumb_mcp.x   # positive = user's right
thumb_vy  = thumb_tip.y - thumb_mcp.y   # positive = downward in image

threshold = self.thumb_threshold   # default 0.06

if abs(thumb_vy) >= abs(thumb_vx):
    # Vertical motion dominates
    if thumb_vy < -threshold:
        control_msg.speed_x =  self.command_linear_speed  # thumb UP ??forward
    elif thumb_vy > threshold:
        control_msg.speed_x = -self.command_linear_speed  # thumb DOWN ??reverse
else:
    # Horizontal motion dominates (mirror-corrected)
    if thumb_vx < -threshold:
        control_msg.speed_y =  self.command_linear_speed  # user left ??car right
    elif thumb_vx > threshold:
        control_msg.speed_y = -self.command_linear_speed  # user right ??car left

05 / Parameters

Tunable parameters

All thresholds and speeds are exposed as ROS2 parameters so you can tune the sensitivity without recompiling. Increase thumb_threshold if the robot reacts to small thumb wobbles; decrease curl_ratio if you want a stricter fist check.

gesture_to_car_control_node.py ??parameters 
self.declare_parameter('input_gesture_topic',   'raw_gesture_data')
self.declare_parameter('output_control_topic',  '/car_movement_control')
self.declare_parameter('enabled_topic',         'gesture_control_enabled')

# Minimum thumb displacement to count as a directional command
self.declare_parameter('thumb_threshold',       0.06)

# Curl check: tip?“wrist < PIP?“wrist ? ratio ??finger is curled
self.declare_parameter('curl_ratio',            1.0)

# Extend check: tip?“wrist ??MCP?“wrist ? ratio ??thumb is out
self.declare_parameter('thumb_extend_ratio',    1.1)

# Speed issued when a valid gesture is detected
self.declare_parameter('command_linear_speed',  0.3)   # [m/s]

# Whether gesture mode starts enabled (joystick toggles this)
self.declare_parameter('default_enabled',       False)
06 / Enable / Disable

Enable / disable via latched topic

Gesture control starts disabled by default (default_enabled: False). The joystick node publishes a Bool on the gesture_control_enabled topic to turn it on. Because that topic uses TRANSIENT_LOCAL (latched) QoS, the gesture node receives the current state immediately on startup, even if the joystick node started first.

enabled_callback 
def enabled_callback(self, msg):
    if msg.data != self.enabled:
        self.enabled = msg.data
        self.get_logger().info(
            f'?‹å‹¢?§è? -> {"?‹å?" if self.enabled else "?œé?"}')
        if not self.enabled:
            self.publish_stop()   # immediately stop the robot when disabled

While disabled, every incoming Gesture message is answered with a stop command ??the robot won't move even if the hand is in frame.

07 / Launch

Running the node

Gesture control requires the camera and the perception node to be running alongside the decision node. The bring-up launch file handles everything in one shot.

terminal 
# Full bring-up ??gesture enabled by default
ros2 launch bring_up bring_up.launch.py

# Gesture only (no hardware, no joystick)
ros2 launch bring_up bring_up.launch.py \
  use_joy:=false use_hardware:=false

# Run the decision node standalone (requires perception node separately)
ros2 run decision gesture_to_car_control_node \
  --ros-args \
  -p command_linear_speed:=0.2 \
  -p default_enabled:=true

# Watch gesture decisions in real time
ros2 topic echo /car_movement_control

# Enable gesture mode from the command line (without the joystick button)
ros2 topic pub --once gesture_control_enabled std_msgs/msg/Bool "data: true"

Hold your right hand in front of the camera with four fingers curled into a fist. Point your thumb upward ??the robot drives forward. Rotate your thumb to the side and it strafes. Let the fist open or lower the hand below frame and the node publishes a stop.
