LAB.02a / Joystick Teleop 搖桿遙控教學

Driving the AGV
with a gamepad joystick

The joy_to_car_control_node sits between the ROS2 joy driver and the car's control layer. It reads normalised axis values from /joy, applies a deadzone, converts them to physical speeds and publishes a CarControl message — and lets you toggle the gesture-control mode without leaving your gamepad.

01 / Concept

How the node fits into the stack

The robot's teleop pipeline has two layers. The joy driver (from the joy package) reads raw USB HID events and publishes them as a sensor_msgs/Joy message on the /joy topic. The decision node —joy_to_car_control_node —translates that into the project's own CarControl message and forwards it downstream.

  • /joy —sensor_msgs/msg/Joy —raw normalised axes & buttons from the gamepad.
  • /car_movement_control —interface/msg/CarControl —physical speed commands (m/s, rad/s).
  • gesture_control_enabled —std_msgs/msg/Bool —latched toggle so other nodes always get the current state.
02 / Install

Install the ROS2 joy driver

Before running the node, make sure the joy package is installed and your gamepad is accessible. The driver publishes on /joy automatically once it detects the device.

terminal 
# Install the joy driver (ROS2 Humble / Iron)
sudo apt install ros-$ROS_DISTRO-joy

# Check your gamepad is visible to the OS
ls /dev/input/js*       # should show js0 (or js1)

# Launch the joy driver standalone to verify
ros2 run joy joy_node

# In another terminal, watch the raw axis data
ros2 topic echo /joy

You should see axes values swing between -1.0 and 1.0 as you move the sticks, and buttons entries flip between 0 and 1 when pressed.

03 / Axis Map

Axis mapping & parameters

Different gamepads expose axes in a different order. The node declares three ROS2 parameters so the mapping can be changed without editing the code. The defaults match a standard Xbox/PS-style controller connected over USB.

joy_to_car_control_node.py — parameters 
self.declare_parameter('joy_topic',              'joy')
self.declare_parameter('output_control_topic',   '/car_movement_control')
self.declare_parameter('gesture_enabled_topic',  'gesture_control_enabled')

# Which axis index controls each motion direction
self.declare_parameter('axis_linear_x',  1)   # forward / backward
self.declare_parameter('axis_linear_y',  0)   # left / right (strafe)
self.declare_parameter('axis_angular_z', 2)   # rotate CW / CCW

# Deadzone: axis values smaller than this are treated as zero
self.declare_parameter('deadzone', 0.01)

# Speed limits: normalised axis value [-1,1] * max = real speed
self.declare_parameter('max_linear_speed',  0.5)   # [m/s]
self.declare_parameter('max_angular_speed', 1.0)   # [rad/s]

# Which button (buttons[] index) toggles gesture mode
self.declare_parameter('gesture_toggle_button',          9)
self.declare_parameter('gesture_control_default_enabled', False)

To override a parameter at launch time, add --ros-args -p axis_linear_x:=3 on the command line, or set it in the bring-up launch file's parameters list.

04 / Deadzone

Deadzone & speed conversion

Analog sticks always have a small resting noise. The deadzone discards any axis value whose absolute magnitude is below the threshold, preventing the robot from drifting when the stick is untouched.

joy_callback — axis -> speed 
# Read normalised axis values  [-1.0 -> +1.0]
forward_backward = msg.axes[self.axis_linear_x]   # +1 = forward, -1 = back
left_right       = msg.axes[self.axis_linear_y]   # +1 = left,    -1 = right
cw_ccw           = msg.axes[self.axis_angular_z]  # +1 = CCW,     -1 = CW

threshold = self.deadzone

# Apply deadzone then scale to real physical units
if abs(forward_backward) > threshold:
    control_msg.speed_x  = forward_backward * self.max_linear_speed

if abs(left_right) > threshold:
    control_msg.speed_y  = left_right * self.max_linear_speed

if abs(cw_ccw) > threshold:
    control_msg.rotate_z = cw_ccw * self.max_angular_speed

Axes that stay within the deadzone leave their corresponding field at 0.0 in the outgoing message, which the mecanum drive interprets as that degree-of-freedom staying still.

05 / Toggle

Gesture-mode toggle button

Button 9 (configurable) on the gamepad toggles the gesture-control layer on or off. The logic is edge-triggered: it fires once on the falling edge (button pressed), not on every tick while it is held down. The state is published on a latched QoS topic so any node that starts later —like the OLED display —immediately receives the current state.

handle_gesture_toggle 
def handle_gesture_toggle(self, msg):
    # Edge detection: only act when button transitions from released -> pressed
    if self.gesture_toggle_button >= len(msg.buttons):
        return
    pressed = msg.buttons[self.gesture_toggle_button] == 1
    if pressed and not self.prev_toggle_pressed:
        self.gesture_enabled = not self.gesture_enabled
        self.get_logger().info(
            f'手勢控制 -> {"啟用" if self.gesture_enabled else "停用"}')
        self.publish_gesture_enabled()   # latched QoS publish
    self.prev_toggle_pressed = pressed

The gesture_control_enabled topic uses TRANSIENT_LOCAL durability so even nodes that subscribe after this one publishes will receive the most recent value —no missed updates.

06 / Launch

Running the node

The easiest way to start the full teleop stack is through the bring-up launch file. You can also launch individual nodes for development or debugging.

terminal 
# Full bring-up (joy + gesture + hardware all enabled by default)
ros2 launch bring_up bring_up.launch.py

# Joy only —disable other inputs
ros2 launch bring_up bring_up.launch.py \
  use_keyboard:=false use_gesture:=false

# Run just the joy_to_car_control_node manually
ros2 run decision joy_to_car_control_node \
  --ros-args \
  -p max_linear_speed:=0.3 \
  -p deadzone:=0.05

# Watch the output CarControl messages
ros2 topic echo /car_movement_control

Once the node is running, push the left stick forward —you should see speed_x climb toward 0.5 (or your configured max). Strafe with the right stick and watch speed_y respond. The mecanum wheels handle all three axes simultaneously.

07 / CarControl

The CarControl message

The node publishes a custom interface/msg/CarControl message instead of the standard geometry_msgs/Twist. This lets it carry extra fields —a mode flag, a header timestamp, and separate linear axes —so the control layer downstream can route commands from different sources (joystick, gesture, keyboard) through the same topic.

CarControl fields (relevant subset) 
std_msgs/Header header       # timestamp
uint8  mode                  # MODE_MANUAL = joystick
float32 speed_x              # forward/backward  [m/s]
float32 speed_y              # left/right strafe  [m/s]
float32 rotate_z             # yaw rate           [rad/s]

The car_control_to_cmd_vel_node downstream converts these fields into a standard geometry_msgs/Twist on /cmd_vel, which the hardware bridge and Gazebo plugin both understand.
